# 北京科技大学科研汇报 HTML 模板

本目录是可复制的本地模板包。入口为 `template.html`，当前提供 20 页版式参考。实际汇报的页数和内容由任务决定，不要求保留全部示例，也不代表已安装到模板库。

### 安装后的定位与输出

本技能的资源根目录是**当前 SKILL.md 所在目录**，不是用户当前工作目录。先从这里读取 `template.html`、`assets/`、`scripts/` 和学习材料；不要假定用户项目内已有 `beike-ppt-template/`。下文示例中的 `beike-ppt-template/` 指模板包根目录，执行命令时按实际技能目录解析。若用户只说制作 slide，应默认使用本技能制作 HTML 幻灯片；若明确要求 PPTX，则不能把 HTML 改扩展名冒充 PPTX，应说明输出形式并按所需格式选择相应工具。

安装目录中的模板、缓存与资产属于母版。制作具体汇报时，将 `template.html` 与所需 `assets/` 复制到用户指定输出目录（未指定时使用当前项目内清楚命名的新目录），然后修改副本。导出、公式重绘与缓存更新使用本技能 `scripts/` 中的脚本，并将副本 HTML 的绝对路径作为参数传入，不能因脚本默认路径而误改或导出安装目录中的母版。保存最终 HTML、PDF 及必要资产到用户项目，不要求用户打开技能安装目录。

## 接到任务后

先读取用户提供的论文、实验记录、文字与图片，再读 `template.html` 的 CSS、目标页和底部交互脚本。以本文件规定的母版为准，按实际证据加工内容，不把示例中的排版说明带进科研汇报。

从现有信息确定汇报主题、听众、时长或页数、已有成果和待讨论问题。只对无法从材料推断且会影响结果的信息提问。材料已经充分时直接制作，常规版式选择不需逐项确认。

默认另存汇报副本，保留母版。用户明确要求修改模板时才编辑本目录的 `template.html`。输出到其他目录时，一并复制所需 `assets/`，或将图片嵌入 HTML，不能留下只在原目录有效的图片路径。

内容先按“本页主题、正文首句、主要证据、必要解释、来源与备注”组织，再挑合适的示例页复制。正文首句可以省略；保留时必须是正文的第一段，不是标题区副标题。

## 母版中保持一致的部分

### 章节顺序与标签

模板按 **封面 → 00 整体规范 → 目录 → 01 研究背景 → 02 研究方法 → 03 实验与分析 → 04 总结与计划 → 附录 → 结束页** 排列。字号、留白与配色等模板说明放在目录前，左上角和侧栏统一写 **00 整体规范**；目录自身用不带章节号的“汇报概览”，不占用 01。实际科研汇报通常删除规范示例页，正文仍从 01 开始。

每一正文章节先放对应过渡页，再连续展示该章的全部正文，完成本章后才进入下一章过渡页。章节号从 **01 连续递增**，不得出现 01 → 03、02 → 03 → 02，或把属于方法的伪代码插到实验结果之后。具体章节名称可按真实研究调整，但目录、过渡页、正文左上标签与 `data-group` 的章节号、名称及顺序必须一致；`data-label` 保留该页具体主题。

参考文献、资料来源及补充材料独立归入 **附录**，不得并入“总结与计划”，也不续编为 05 等正文章节号。使用 `<span class="section-index appendix-index" data-edit>附录</span>`，其后写资料类别，侧栏 `data-group="附录"`。多页附录沿用此标签；如需区分材料，修改各页标题和侧栏短标题。文献条目的稳定锚点与具体页码无关，重排后必须复查脚注跳转。结束页单独分组。

复制、插入或重排后，按实际页序核对整份文稿，不能只修改单页的左上数字。模板 `checkLayout()` 同时检查规范页位置、章节递增、正文归属、目录对应和侧栏分组；仍须目视确认本章内容已完整展示，再切换下一章。

### 画布与安全区域

- 原始画布为 **1600×900 CSS px，16:9**。预览整体缩放，不改变画布内各元素的相对位置。
- 左右安全边距均为 **58px**。正文区为 **x=58…1542，y=192…810**，宽 1484px、高 618px。
- `.slide-header` 高 **168px**。章节标签从 y=34px 开始，主标题位于其下。分割线在标题区底部，横跨左右安全边距。
- 正文顺序为 **大标题 → 分割线 → 正文首句 → 图文或表格**。`.lead` 放在 `.slide-content` 内；不要在首句下方再加第二道线。
- 页脚独立固定在底部，高 **50px**，与正文区至少相隔 12px。图注和结论条占正文区内的真实高度。右下使用 `.footer-source` 放本页文献、实验记录或图像出处，最右独立显示页码，**不再重复左上角章节名称**。来源没有可填内容时留空，不为填满页脚杜撰文献；长出处放备注，页脚保留可定位的短引文。
- 删除原来的左上角蓝色方块，不再生成 `.badge-top`。正文顶部只保留 **7px** 细装饰条。

### 封面与结束页

二者均使用 `.slide.cover`，结束页只额外添加 `.closing` 语义类。**不为 `.closing` 单独覆盖字号、条带高度或标志尺寸。**

- 顶部标志区 235px。
- 蓝色条带 330px，左右内边距 90px。
- 标题统一 **PPT 40pt，画布约 67px、700 字重、1.3 行高、4px 字距**，最多两行，封面和尾页共用字号与字距变量。
- 条带副文字 14pt；底部汇报信息的标签 16pt，值 18pt，均按下述比例反算画布 px。
- 署名使用一张无边框 **两列表格** `table.cover-info`，整表居中。左列统一宽 **112px**，标签用 `th > span` 的 `text-align-last:justify` 两端对齐；右列统一左对齐。单元格水平间隔 **28px**、垂直间隔 **12px**。学院名称再长也不能改变某一行的左起位置；不要把各行做成独立居中的 flex 或 grid。
- 使用实际姓名、导师、学院和日期。无来源的信息不代填；不需要的字段可以删掉。
- 结束用语采用“感谢聆听，恳请批评指正”等得体表达，长度控制在同一字号可容纳的范围。

### 字体与字号

所有 px 数值均指 1600×900 原始画布，不能与预览缩放后的屏幕像素混用。**PowerPoint 的等效字号还取决于幻灯片的物理尺寸，不能直接套用 CSS 的 px→pt 换算。**

本模板按 PowerPoint 常用宽屏 **13⅓×7.5 英寸，即 960×540pt** 对应整个画布。因此 **等效 PPT pt＝画布 px×960/1600＝画布 px×0.6**。CSS 自身的单位关系为 **CSS pt＝CSS px×0.75**，是另一口径。依据：[微软的幻灯片尺寸说明](https://support.microsoft.com/zh-cn/powerpoint/change-the-size-of-your-powerpoint-slides)、[W3C 的绝对长度单位](https://www.w3.org/Style/Examples/007/units.html)。

字号先对齐用户指定的常用 PPT 档位：**10、11、12、14、16、18、20、24、28、32、36、40、44、48、54、60、66、72、80、88、96pt**。用户列出的 10.5pt 可作参照，但当前明确要求整数，因此默认不选小数档位。不能只把 15.6pt 显示成 16pt 而仍保留原字号；样式应从选定的 pt 档位反算。CSS 内部可以保留反算精度，面向用户的换算表取整数并标注“约”。

| 层级 | 画布字号 px（约） | PPT pt | 补充要求 |
|---|---:|---:|---|
| 封面 / 结束页标题 | 67 | 40 | 两页共用 `--fs-cover-title` |
| 正文主标题 | 47 | 28 | 优先一行，最终以渲染为准 |
| 分组标题 | 33 | 20 | `h3.group-title`，如“阶段总结”“下一步计划” |
| 板块 / 公式题目 | 30 | 18 | 高于正文，题目加粗；公式题目采用深底白字 |
| 分项标题 | 30 | 18 | `h4.item-title`，低于所属分组标题 |
| 独立公式 | 27 | 16 | 共用 `--fs-equation`，正文公式与符号 SVG 统一数学字形 |
| 正文首句与公式解释 | 27 | 16 | 行高约 1.5–1.6，首句最多两行 |
| 表格内文字 | 13–23 | 8–14 | 总体参考范围，按列宽、内容密度与阅读距离选择整数档位 |
| 伪代码 | 23 | 14 | 控制流程与输入输出分开排布 |
| 密集实验比较表 | 20 / 18 / 17 | 12 / 11 / 10 | 由大到小试排整数档位，始终大于 8pt、小于 14pt |
| 图标题 | 23 | 14 | `.figure figcaption strong`，图号与标题同一层级 |
| 图注说明 | 20 | 12 | `.figure-caption-detail`，在图标题下方另占一行 |
| 补充来源 / 页脚 / 页码 | 17 | 约 10 | 10÷0.6 四舍五入为 17px，不再使用 14px 小字 |

模板 P02 的 px 与 pt 列由 `syncTypeScale()` 根据字号变量自动同步。更改 PowerPoint 实际页面尺寸时，更新 `--ppt-width-pt`，按新比例重算，并同步打印页面与缩放。不能因为都叫“16:9”就认为物理字号相同。

P02 的“表格内文字”应展示总体 **8–14pt（画布约 13–23px）**，不能仅列 10 / 11 / 12pt 而把某个示例的自适应档位误写成全部表格的字号规范。P12 仍以 12pt 为基准，按 12 / 11 / 10pt 试排；P16 的计划表为 14pt。图标题独立使用 `--fs-figure-title`，不要把共享的 `--fs-caption` 一起加大而影响表格、图注说明和其他辅助文字。

标题按实际语义分层：页面标题 `h2`、分组 `h3.group-title`、分项 `h4.item-title`。上一级至少高一个常用字号档位；不能只依靠字重区分，不能把父标题和子标题都设成同一级 h3。总结页使用 **28pt 页面标题 → 20pt 分组 → 18pt 分项 → 16pt 正文**。

正文中的强调句、口号和卡片文字也受页面标题层级约束，不能因重要或加粗就放大到主标题以上；强调字默认低于主标题。P02“清楚表达 / 留出呼吸”使用 **20pt**，其下卡片标题为 **18pt**、列表文字为 **14pt**，页面主标题仍为 **28pt**。标题与内容必须同时有字号层级和适当字重区分，不能只把同字号文字加粗就当作标题。章节过渡页及目录装饰性编号按各自版式处理。

中文优先 `Microsoft YaHei`，后备 `PingFang SC`、`Noto Sans CJK SC`。英文用 Arial 等常见无衬线字体，伪代码用 Consolas，数值启用 `tabular-nums`。除必要数学符号外，不依赖系统中未确认安装的字体。

正文过满时先删重复内容，再调整分栏比例或拆页。不要用 `overflow:hidden`、负边距、绝对定位覆盖或小字号掩盖超量内容。即使画布本身隐藏溢出，也要检查实际文字边界。

正文也不能因过度稀疏而留下大块完整空白。保留 20–28px 左右的必要间距；内容较少时优先放大主图或表格、合并相关内容、改用横向列表，或把证据说明放到相邻位置，不用 `space-between` 强行拉出巨大间隔。目录、表格、参考文献和总结页都要检查中部与底部是否形成连续的空白带。封面、尾页及章节过渡的留白可以更宽松。不要用空话、装饰卡片或伪造数据填满页面。

**逐页追求内容充实、主次明确，同时保持必要呼吸感。** 除整页外，还要分别检查每一栏：主图很大不代表文字栏已平衡，满高的空容器也不等于内容丰满。若右栏只有两段短文而下半栏整块空置，先从现有图像或材料中提炼有依据的观察、解释、比较条件及局限；再按阅读顺序组织小标题、正文或列表。补充内容仍须服务本页主题。材料确实较少时，调整图文比例、合并页面或换版式；不能仅增加卡片数量、拉大段距、强撑卡片高度，或降低字号堆入无关内容。

**并列内容既要检查顶部，也要检查实际底边和末行。** 对同一层级的左右说明、卡片或图文区域，优先让可见背景／边框的下沿对齐，不能仅让两个空容器等高、实际内容却一边提前结束。同字号的并列末行还应尽量处在同一视觉高度，检查真实文字位置，不只看元素的名义高度。可通过共同的 grid／flex 容器、合理的下内边距和末块的 `margin-top:auto` 调整剩余空间；不能靠绝对定位、负边距、裁剪、巨大空框或过大的中间空隙硬拉齐。按语义整理末段也可改善对齐，例如 P16 将讨论事项与时间说明分成完整两行，再与左栏底部齐平。P02 的两栏底部说明、P13 的主图与末尾提示卡片、P19 的身份栏与最后一个研究方向板块均作了对应处理。

对齐要按语义判断：同级同字号的说明适合校齐末行；不同字号的图注与正文优先校齐模块边界；伪代码保持自然流程，不为追求末行齐平拉散代码。参考文献的序号列继续与条目**首行**顶端对齐，不能套用末行对齐规则。每次换内容后重新检查，避免一处调高造成另一处超出安全区或遮住页脚。

将措辞、信息结构和版式一起调整：说明文字下方明显过空时，先判断是否值得提炼一个具体小标题，再按完整含义分成两段，适量补全条件、对象或区别；内容拥挤时删去重复表达，保留判断所需的信息。P02“换算说明”采用 **18pt 小标题＋12pt 正文**，第一段说明 PPT 换算及取整，第二段说明 CSS 换算与口径差异，各自完整占行。这类同一主题的连贯解释使用段落，独立并列提示则使用列表。按实际字数协调表格内边距、段距和上下空间，再复查阅读顺序、短尾行与边界。增删文字必须保持事实、公式、证据和适用条件准确，扩写需增加实际信息，不能为撑满版面编造结果。制作真实 Slide 时同样主动进行这一步编辑，不等待用户逐处指出。

**全页文字都要检查段末孤字和短尾行，而不只检查公式解释。** 如果自动换行后末行仅剩一至三个汉字（如“化。”“计方式。”），先在保持原意、证据与限定条件的前提下适量增删或改写；必要时按完整语义拆成长度较均衡的句子或列表项。更长的尾行也要结合栏宽判断，不能仅因为超过三个字就认定排版合格。不得仅缩小某一段、加无意义字句、强行两端撑开或逐字插入空格。正文、标题、列表、表格、图注、卡片和页脚来源均适用；手动 `<br>` 也需在实际画布中复查，不能截断变量、数值与单位。模板 P02 有可见提醒，`checkLayout()` 使用实际字符坐标提示一至三个字符的末行问题。

多句文本末行明显偏短时，还要判断能否**一句一行或一句一段**。独立、并列的建议或结论优先用真实 `<ul class="points" role="list">`，每句一个 `<li data-edit>`，不要只用若干 `<br>` 形成没有前导符的列表。P02 的“换行与对齐”和字体建议均为示例。有明确承接关系的公式解释或连续论证可保留自然段 / 语义分行；先保证语义完整，再比较阅读节奏与空间。不能见到句号就机械拆项、把连贯论证拆碎，或制造更多短行与越界。

无序列表使用统一 `.points` 样式：圆点约 **6px**，从圆点右缘到文字左缘的距离为 `--bullet-gap:24px`。按本模板物理比例，**PPT 0.5cm ≈14pt，反算为约 24px 的原始画布间距**；不能直接给浏览器写 `0.5cm` 而忽略整体缩放。圆点和文字共占约 30px 缩进，续行与首行文字对齐，不退回圆点处。采用 CSS 前导符时保留真实 ul/li 及 `role="list"`；不手打圆点加空格，不用空白字符凑距离。修改间距后重新检查窄栏换行与孤字，现有 P06 列表也共用这套规则。

**任何内容块相互遮盖都不允许，包括覆盖表格的空白单元格区域。** 表格、图注和下方说明按正常文档流依次排列，说明与表格至少间隔 12px。不要给普通计划表强制 `height:100%`，再把其包装器设为 `flex:1;min-height:0`，这会使真实表格高于容器而被下方文字块覆盖。P16 计划表采用 14pt，任务与产出按完整短语分行；按自然高度排布，上下内边距 8px、左右 12px，行高约 1.45；不足以容纳时改写内容、调整列宽或拆页，不能盖住、裁掉或挪出安全区。为避免留白而强撑表格行高同样不可取。

### 四阶段图文研究现状

P07 位于 **01 研究背景**，页标题为“研究现状分析”，以校史作版式示例。保留标题分割线下方的 `.lead` 页首句，最多两行；其后使用 `.history-timeline` 等宽四列、16px 列间距、两侧各内缩32px。各列从上到下为 **24pt 加粗年份 → 同尺寸图片 → 14pt 说明段落**，上方仅放年份；**18pt 加粗阶段标题移到底部浅色大箭头上**，不能上下重复。年份栏按序使用 `#005B94`、`#0B709D`、`#1885AC`、`#2692AC`，白字；后面三种是此页阶段区分色，不冒称学校官方标准色。图片与说明置于同一块连续的浅蓝底 `#F1F7FB` 上，间隔也保留该底色，不用白色空带切断图文关系；各列文字齐顶，图片上下沿与文字框底边对齐。页首句和说明段落均 `text-align:justify; text-align-last:left`，两端对齐、末行自然左对齐，不分散短行、不手动插空格撑齐。

四张图统一 `width:calc(100% - 32px);margin:0 16px;height:148px;object-fit:cover`，在当前画布下各为 **311×148px** 的等比裁切视窗；通过 `object-position` 保护校名、建筑或研究对象主体，不能拉伸，也不能只统一宽度而保留参差高度。保留原图供重新裁切。**年份栏至图片、图片至文字块均留16px可见空隙**，四列使用相同间距；文字块另保留上下10px、左右16px内边距。不能让图片与文字块贴合，也不能某一列单独加大空隙。

底部时间轴独占 **58px** 高的一行，与上方文字框间隔16px，使用浅色大箭头承载四个阶段标题。每个圆点的**圆心与对应文字框左边缘对齐**，并用连续竖线沿图文框左沿从圆心一直延伸到上方年份色块顶端，线段顶端与色块顶端齐平，不在色块底边提前停止；阶段框内的线与下方16px间隔中的线须同轴衔接，不能把点居中于列或让连接线悬空。标题位于圆点右侧，箭头、圆点、连线均不得覆盖文字；圆点直径16px，外轮廓完整落在浅色箭头内部，不得将首个圆点露出半个在箭头外。箭头宽于四列内容区域，左右各多留32px，圆点及阶段标题均保留必要净空。正文首句、年份栏、图片、段落、时间轴都占真实高度。段落默认约五行，不能为凑列数堆空话、缩小字号或制造短尾行。内容超量时删去重复措辞、调整图高或拆页；不得用裁剪或负边距掩盖实际内容溢出。

真实研究汇报中把四阶段替换为技术演进或代表工作，写明相应贡献、能力与局限，关联真实来源。图片文件名不等于拍摄日期，更不能把校园配图说成雄安校区实景。年份、机构名称、前沿平台与建设状态需要核对。新增页面后同步静态页码、总页数、导航、说明表及 PDF，不能只依靠脚本临时改编号。

### 附录中的参考文献

参考文献应有独立附录页，不与作者简介、未来计划或模板制作来源混为一页。以 **GB/T 7714-2025《信息与文献 参考文献著录规则》** 为依据，若用户提供 `新国标参考文献要求.md`，可结合该学习笔记核对所需类型与字段；缺少此文件时依据标准及真实文献元数据处理，不把笔记当作运行依赖，也不以其代替标准正文。标准信息可核对[国家标准公开页面](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=C6CE52E55AC09B9C79A20AEA77CEDD14)。P18 示例覆盖制作时所用材料的 **J、M、N、D、C、S、P、R、EB、DS、PP 共 11 类**，不是国家标准全部文献类型的穷举。实际汇报只列确实引用的文献，不保留为了展示类型而添加的教学条目。

文献类型依据资源本体判断，不能因为从网上取得就一律写 `[EB/OL]`。`/OL` 是联机载体，可与 J、R、DS、PP 等相应类型组合。按类型核对作者、题名、版本、出版信息、日期、卷期页码、专利或标准编号等字段；在线资源按适用规则补充更新／发布日期、引用日期、版本及具体访问路径，保留已核实的永久标识符。日期与版本不得凭空补齐。责任者不超过三位时全部著录，超过三位时可列前三位并加“等”或“et al”；西文姓名、缩写与名间空格依据原文与新标准统一处理。

按 2025 版的类型规则分别处理必备项：DS 与 PP 的引用日期必备；DS 的版本可选，PP 的版本有则必备；不因示例有某字段就推断所有类型一律必填。标准类文献的 `[S]` 是可选项，示例为展示类型而保留。

采用用户明确要求的 **英文半角标点**：`.`、`,`、`:`、`;`、`()`、`[]`、`""` 等。作为著录分隔符的句点、逗号、冒号和分号后留 **一个半角空格**，中英文条目相同；标点前不加空格。题名中的中文引号、书名号和卷期括号按这一排版要求统一，保持题名可识别。**不能对整条文本机械执行“所有标点后加空格”**：网址、DOI、专利号、报告编号、版本号、日期、数字与原有缩写内部的标点需保持完整，不能把 `https://`、`10.48550/…` 或 `CN200610171314.3` 拆坏；结尾分隔句点不算网址本体。该空格策略是本模板的统一排版约定，不把它冒称为国家标准要求所有内部标点一律加空格。

参考文献使用 **无表头、无框线、白底的两列表格** `.bibliography-table`：第一列仅放 `[1]` 等顺序号，默认宽 **48px**、右内边距 **6px**；第二列为完整条目，**不额外添加左内边距**。序号列按最长编号预留必要空间，不能过宽而把正文推远；位数增加时按真实文字宽度适量加宽。**所有单元格顶端对齐，序号左对齐，条目正文两端对齐、末行左对齐**：正文使用 `text-align:justify; text-align-last:left; text-justify:inter-word`，正常英文单词不拆散，不用分散对齐、强制字距或手动空格撑满短行。条目自动换行后保持相同文字起点，编号与首行对齐。不可套用有深色表头或交替底色的普通数据表样式，不用空格、制表符或整段悬挂缩进替代编号列。

**同一条目内部的行距与相邻条目之间的距离必须有明显区别**：条目内部相对紧凑，条目之间留出更多空白，避免两行参考文献与下一条看成同一个文字组。默认 **12pt、1.35 行高、单元格上内边距 6px／下内边距 7px**，相邻条目合计增加 13px 的留白；不要只增大文本行距而让条目之间同样松散，也不要用固定单元格高度裁剪多行文字。调整后按实际换行检查底部边界，必要时拆页，不能挤压页脚。按实际内容在表格 8–14pt 范围内选择常用整数档位，优先改写辅助说明或拆页，保留可读字号。**表格内的 URL／DOI 不能当作不可拆分的英文单词**：链接元素和 `.reference-link` 使用 `white-space:normal; overflow-wrap:anywhere; word-break:normal`，优先利用路径标点自然断行，过长片段也允许换行。日期使用 `.reference-date`，可在连字符后及相邻括号组之间添加 `<wbr>`，例如 `(2012-<wbr>03-<wbr>18)<wbr>[2020-<wbr>06-<wbr>24]`；不在数字内部硬断，不让右括号单独成为行首。短标识符可按空间用 `.reference-token` 保持完整，不能把此样式套在 URL／DOI 或整个日期组合上。软换行不添加实际空格、连字符或零宽字符，复制内容及链接 href 必须保持原样。检查非末行左右边缘齐平、末行自然左对齐，避免分散对齐。文献多时分成多个附录页，编号连续，不把全部条目硬压在一页。`checkLayout()` 检查两列结构、无表头、对齐方式与中英文标点，分隔符空格和元数据仍需复查。

每条文献的稳定 ID 放在对应 `tr` 上，例如 `<tr id="ref-paper-chen-2026"><td data-edit>[3]</td><td data-edit>完整条目</td></tr>`，不随页面编号变化。脚注可链接这个 ID，跨多页参考文献仍须定位正确条目。引用网页与 DOI 应使用核实后的真实链接；不得猜 DOI 或用教学条目支持研究结论。P18 的示例条目整理自用户资料，只用于格式演示，正式汇报须核对文献原文、元数据与链接后替换。

### 附录中的作者简介

附录不仅可放参考资料，也可放作者简介、团队说明或必要补充材料。作者简介采用 P19 的 `.profile-layout`：左侧约 **340px** 放照片、姓名、职称／学位、学院或机构、团队和联系邮箱；右侧按顺序保留 **教育和工作经历、主要学术任职／代表性项目（奖项）、主要研究方向**。用同一正文母版与“附录”标签，不续编正文章节号。简介页可省略正文首句，为履历保留完整的正文高度。

教育与工作经历默认按时间顺序填写“起止时间、学校／工作单位、学位／专业／职务”，示例三行按真实经历增删。履历表采用 **五列**：第 **1／3／5 列放文字**，第 **2／4 列为空白间隔**。两列间隔各为表格正文字号的 **0.5em**，在当前 12pt／画布 20px 下仅 **10px**，不能加宽成大块留白。间隔单元格为空、不设内边距、不画任何边线；表头三个内容单元格为白底深色字，仅在下方各画一条分割线，三段横线在空白列处断开。不使用深色表头底，也不让全行底色跨过间隔列。表头 **14pt**，正文 **12pt**，正文与“学术组织／期刊：职务”等辅助说明字号一致；表头和正文均水平居中、顶端对齐。这个居中规则仅用于履历表，不能覆盖参考文献表的顶端对齐、序号左对齐及正文两端对齐要求。

任职写明组织、职务与任期；项目写明名称及本人角色；奖项注明名称、年份及必要排名。任职或成果较少时可以合并该区，按用户要求保留应有项目的填写位置。研究方向示例三列，每列保留具体对象、问题、方法或应用字段；按实际信息量调整列数，不堆砌没有解释的方向标签。履历过长时拆成多张附录，不覆盖相邻板块，不把文字压到难以阅读。

左侧姓名和成果数字 **20pt**，右侧分组题目 **18pt**，身份文字、履历表头及分项标题 **14pt**，履历表正文、辅助字段与列表 **12pt**；字号和字重同时区分层级。作者简介页不显示“待填写”字样：保留字段名称，普通字段缺值时留空，同时删除原来包裹提示的空括号或方括号。**论文与项目数量保留加粗的大号数字占位 `XX`**，下方分别标“论文（篇）”“项目（项）”，不能把数字占位一起删除；真实材料到位后再替换，不用零冒充未知值。履历表上下内边距默认各 **5px**，保持自然行高，复查三个板块均在正文安全区内。采用平直的科技蓝题目条、白色正文和一处浅蓝身份栏，与其他正文页保持一致；不照搬参考图的斜切飘带、虚线大框、重阴影或夸张统计数字。

身份栏浅蓝框下沿须与右侧最后一个研究方向板块下沿齐平，左右最底部的 **12pt** 标签／说明末行也保持同一视觉高度。`.profile-metrics` 用自动上边距把数量区放到底部；左栏下内边距为 **12px**，与右侧研究方向正文的下内边距一致。右侧最后一块使用剩余高度，各方向列表在其内部底部对齐；不要给不同内容分别猜绝对高度。修改履历行数、照片尺寸或研究方向文字后复查真实底边与末行，不只确认外层 `.profile-layout` 等高。

`assets/avatar-placeholder.svg` 是通用人物轮廓占位，不对应任何真实人物。可换成用户提供的正式照片，保持比例并完整展示面部；用户允许时也可采用符合全篇风格的卡通头像。参考图仅用于学习信息结构，不能把其中人物的姓名、照片、学术头衔、论文数量或项目成果移植给作者。材料缺失时保留字段名与空值，不编造履历；论文、项目数量等统计只在有可靠材料且对本次介绍有用时添加。替换照片后刷新图片缓存，同时验证保存后重开与 PDF 导出。

### 公式

每个公式独立使用 `.formula-card`：顶部 `.equation-label` 为 **18pt、加粗、深底白字** 的题目条；其下 `.formula-body` 为浅蓝框，两者必须同宽、垂直贴边、没有缝隙。浅色框内放 **16pt 公式和 16pt 正文解释**，不能只有题目与公式，也不能把题目降到正文字号。解释应说明该式做什么、关键项含义或计算约定，避免重复标题。公式卡片根据实际内容分配高度，不用居中短公式与巨大内边距制造空白。

公式以 **`data-tex` 保存 LaTeX 源码**，`data-math-asset` 指定稳定文件名，**每个对象只显示一个 SVG 图片**。正文公式与符号栏统一使用 Cambria Math 的数学字形，经 XeLaTeX 与 dvisvgm 输出字形轮廓，无需浏览器安装数学字体或访问 CDN。SVG 可以任意缩放，不以模糊截图代替。旧模板的 MathML 与 MathJax 双路径曾造成重复公式、字号不一和遮盖，不能重新引入运行时第二份显示结果。

```html
<section class="formula-card">
  <h3 class="equation-label" data-edit>平方变换</h3>
  <div class="formula-body">
    <div class="equation-row">
      <div class="math-expression" data-tex="x^2" data-math-asset="example-square">
        <img class="formula-image" data-math-image="example-square"
             src="assets/math/example-square.svg" style="" alt="x 的平方">
      </div>
      <span class="equation-number">(1)</span>
    </div>
    <p class="equation-explanation" data-edit>将变量 <var>x</var> 自乘，得到对应的平方项。</p>
  </div>
</section>
```

以上是待构建的组件示意，`style` 中的 em 尺寸由脚本生成。编辑公式或符号的 LaTeX 后，运行 `python beike-ppt-template/scripts/render-formulas.py "汇报HTML路径"`，再运行同目录的 `embed-assets.py "汇报HTML路径"` 刷新缓存；默认路径为模板自身。脚本需要 XeLaTeX、dvisvgm 和 Cambria Math，已生成的 SVG 在浏览和保存时不需要这些依赖。只改普通正文无需重绘。新增对象必须给出唯一稳定名称、对应 `img[data-math-image]`、空的或已有的 `style` 属性和准确 `alt`；不能只改源码而留下旧图片。同步公式编号、解释和符号表。长公式先按语义分行或拆页，不靠 `max-width` 压小字形，不使用横向滚动。

数学字形按语义选择，先遵循研究原文的约定，并全篇保持一致：

| 对象 | 字重与字形 | 示例与要求 |
|---|---|---|
| 标量变量、参数、变量下标 | 常规字重、斜体 | `x`、`m`、`\alpha`、`x_i`；正文内使用 `<var>`，不可只换字体而忘记斜体 |
| 需要区分的向量 | 常规采用粗斜体 | unicode-math 的 `\symbfit{x}`、`\symbfit{\theta}`；与原文约定统一，不按重要性随意加粗 |
| 矩阵 | 常规采用粗正体 | `\mathbf{A}`；若原文采用另一约定，应整体沿用 |
| 数字、单位、函数名、说明性下标 | 常规字重、正体 | `12`、`\mathrm{m/s}`、`\sin`、`\log`、`x_{\mathrm{max}}`；自定义算子用 `\operatorname{}` |
| 数学逗号、括号与运算符 | 同一数学字体的正体标点 / 运算符 | 将 `x_i,\,y_i` 整组生成同一 SVG，避免混入普通文本逗号造成字形与间距跳变；标点本身不冒充斜体变量 |
| 正文、解释、补充条件 | 正体、常规字重约 400 | 不使用 300 等细字重承担投影阅读；通过字号和颜色区分辅助说明 |
| 页面题目、公式题目、分组标题 | 正体、加粗约 700 | 用于文本层级；公式变量的粗体语义独立于标题字重 |

P09 公式与符号栏沿用常规数学斜体，不凭视觉强调随意改变变量语义。符号栏也通过 `.math-symbol[data-tex]` 与同一脚本生成整组字形，不手拼逗号、上下标或 Unicode 小字。保存时将这些 SVG 与其他图片一起内嵌。交付前检查每个公式及符号恰好一份可见结果，联网、离线、不同预览尺度以及保存后重开均一致。

模板 P09 右下 `.symbol-note` 为“字体样式说明”，用真实数学 SVG 分别展示常规斜体的标量 / 参数、粗斜体向量、粗正体矩阵和常规正体的数字 / 单位 / 函数；不要只列名称而不展示差异。符号表采用适度紧凑的行距，让说明框与主公式共同利用正文空间，不能通过放大空框或增加无意义段落填满。生成实际研究汇报时，可将这块模板说明改为与研究有关的符号约定或结果解释。

只陈述材料支持的数学结论，写清假设和适用条件。模板中的平方误差、正则项与梯度下降是排版示例，不能直接据此声称某研究方法收敛或性能更优。

### 表格与伪代码

表格使用真实 `<table>`，列宽用 `<colgroup>`，行名使用 `<th scope="row">`。多场景实验采用两级表头：左列算法 `rowspan="2"`，各场景 `scope="colgroup" colspan="指标数"`，下层指标 `scope="col"`；各场景的指标顺序、单位和优劣方向一致。场景与子指标可以增加，但同步检查合并列数、列宽及真实文字边界。数值使用等宽数字；多级表内可居中对齐，简单数值表可右对齐。

**所有列标题层级均用深底白字**，包括“质量 / % ↑”等第二级指标，不能把它们放在白底正文样式中。第一层可用科技蓝、第二层用中蓝。跨多个指标构成的场景列组用竖线划界：蓝底表头使用白线，白色或浅色数据区使用黑线；算法列与场景一之间也划界，组内保持简洁。P12 为每组三指标，CSS 按组边界设置；改变每组指标数时必须同步边界选择器或改用明确的组末类名，不能让分隔线落到组内。

**数值单元格左右内边距至少各为 `0.5em`**，保证相邻列的文字墨迹之间至少有一个字符宽的空间；加粗高亮行也适用。不能以 `scrollWidth <= clientWidth` 作为充分条件，必须验证真实文字边界没有侵入内边距。算法列按真实名称分配宽度；P12 算法列约 12%，余下 88% 分给九个数值列，避免首列大片空白、数值列却相互挤压。变更数据、字体、列数与字重后重新试排，长数字不能通过压缩内边距强塞。

在指标名或单位后使用 **↑ / ↓** 标记优化方向，例如“质量 / % ↑”“耗时 / s ↓”。表头不重复写“越大越好”“越小越好”，在本页表格下方统一说明：**↑ 表示数值越大越优，↓ 表示数值越小越优**。箭头应依据指标的实际定义填写，同一指标跨场景保持一致。

P12 的 `xx.xx ± xx.xx` 是**均值 ± 标准差的格式占位符**，不是真实实验数据。替换时核对重复次数和统计口径，不能混淆标准差、标准误与置信区间。高亮本文方法只表示关注对象，不代表最优。没有数据时保留明确占位符或改为实验设置说明，不制造看似真实的数值。

密集实验表用 `.comparison-wrap > table.adaptive-table[data-adaptive-table]`，基准 `data-base-pt="12"`、可用档位 `data-pt-stops="10,11,12"`，始终处于 **8pt 以上、14pt 以下**。`adjustTables()` 在加载、字体就绪、切换预览、窗口调整及文字编辑后，依次试排 **12、11、10pt**，取能容纳内容的最大整数档位；按 `pt / pptPtPerPx()` 转为 CSS px，不能把 PPT pt 直接当作 CSS pt。行高与上下内边距可联动调整，左右内边距保持至少半个字符。通过 `cellTextFits()` 检查扣除内边距后的实际墨迹边界。P12 密集比较表可使用可用区域高度，普通计划表保持自然高度，两者不能共用强撑满高的规则。10pt 仍放不下时 `checkLayout()` 提示拆分场景或指标，不继续缩字或裁剪。实际汇报可删除 `.table-baseline` 说明条，但保留自适应逻辑。

P12 表格下的“实验口径 / 符号说明”是无底色的两组辅助文字：采用等宽双栏、共同顶线，相对画布中线对称；每组内容各自左对齐，两侧保留相同内缩。默认两组之间 **96px**、外侧内缩各 **24px**，与表格至少间隔 **24px**，通过充分留白区分独立文字组。各组使用 **14pt 独立标题＋12pt 无序列表**，每组两条长度适中的说明。实验条件与统计口径按语义分条，避免把长段落挤成三字尾行。检查容器对称后，还要目视比较实际文字的行数、长短和视觉重心；说明增加时为其预留真实高度，并重新试排表格，任何相互遮盖都须修复。

伪代码用 `.algorithm` 与 `.code-lines` 有序列表，行号自动生成。输入、输出、初始化、循环、分支及停止条件前后相符；缩进与关键词层次清楚，变量与公式页一致。超过容量时按算法阶段拆页，不使用滚动条。

### 图片与图表

使用 `figure.figure > .imgbox > img`，并将 `figcaption` 放在 `.imgbox` 外。图号与图标题使用 `figcaption > strong`，统一 **PPT 14pt（画布约 23px）**；需要补充说明时放在其下 `.figure-caption-detail`，使用 12pt，不能把说明和图标题混成同一层级。图标题和说明各占实际高度，图片区域随之让位。容器使用剩余高度，图片默认 `object-fit:contain`，不裁去坐标、单位、图例或重要细节。纵向大图可单独成页，不能为了凑双图而压成缩略图。

P13 的单图页使用 `.stack.ruled.image-notes`，右栏包含两组可直接从示例图观察到的说明，以及一组浅蓝底的研究图像替换要点。观察正文为 **16pt**，标题 **18pt**，辅助列表 **14pt**；组间约 **20px**，标题与正文、列表项之间保留必要间距，避免底部出现与左图高度明显失衡的整块空白。生成真实汇报时将模板提示改为该研究的证据说明、适用条件或局限，按材料决定分组数量，不要求所有单图页都凑成三块。正文与图注先按真实行高占位，再检查短尾行、拥挤和越界。

模板的三张示例 PNG 均截自随附《北京科技大学多媒体课件视觉规范》，出处已写在对应页。生成实际科研汇报时替换成该研究的真实图像，同时改图注、说明和来源，不把学校模板截图作为科研证据。比较实验图时核对坐标范围、单位、颜色映射、样本与评价口径。

## 内容写法

- 一页围绕一个明确主题。标题直接命名研究对象或有证据支持的发现，避免“全面赋能”“显著提升”等空话。
- 首句补充背景、判断或阅读线索，不重复标题。后续给出相应的图表、公式或具体解释。
- 区分已完成工作、初步观察、假设和计划。结论保留影响判断的实验条件与限制。
- 专有名词、变量和缩写全篇一致。首次出现必要缩写时给出全称或中文解释。
- 引文与数据可追溯到用户材料或核实后的来源。关键证据在对应页标注出处，不只堆到最后。
- **引用文献的页脚必须可点击**：优先链接 DOI 或真实来源网页，也可链接本 HTML 中对应文献条目的稳定锚点，如 `<a href="#ref-paper-chen-2026">[3] Chen 等，2026</a>`。目标条目可位于任意参考文献页，不假设只有最后一页。每条文献的 ID 唯一且不随页码改变，不能把所有文献都指向某一页顶部。模板的 `gotoPage(n,anchorId)` 与 `resolveHash()` 会找到条目所属页面，在单页预览中也切到正确页，重开深链接仍有效。重排页面后复查链接；外部链接必须真实可访问，不猜 DOI。无真实来源的占位说明不伪造超链接。
- 演讲备注用于补充推理、来源和讲述顺序。实际汇报里不保留模板操作说明、布局检查记录或泛泛的占位话。

## 预览、保存与交付前检查

工具栏“视图”提供 **单列滚动、多页滚动、单页展示**。多页滚动默认每行 2 页，可手动选择 **1–6 页**，按页序从左到右、从上到下排列；只缩放整张 1600×900 画布，不改变幻灯片内的字体和布局。单击缩略页选中，双击进入该页的单页展示；编辑文字时双击仍用于编辑。选择其他视图时保持当前页，Esc 从单页展示回到此前的滚动视图和每行页数。

多页视图中，侧栏、上一页 / 下一页、文献链接与当前页标记要对应实际页码，同一行的页面不能在滚动后错误地都选成第一列。工具栏允许换行；正文上边距和侧栏位置由 `fit()` 按工具栏真实高度同步，窄窗口也不能遮住页面。备注位于各页画布之外，展开时由网格自然让位。`checkLayout()` 暂时恢复单列进行检查，完成后恢复原视图、选中页与滚动位置。

单页展示支持方向键、空格、PageUp / PageDown、Home / End，Esc 退出；编辑文字或操作下拉框时，翻页快捷键不抢输入。文字编辑、复制本页、备注和打印功能均保留。

**“全屏放映”独立于普通单页展示。** 通过用户点击请求 Fullscreen API，隐藏工具栏、目录与备注，在屏幕内等比居中显示整张 16:9 画布；不同屏幕比例允许黑边，不裁切、不拉伸。Fullscreen API 不可用或被拒绝时保留窗口放映，并说明降级，不让放映功能整体失效。方向键、空格、PageUp／PageDown、Home／End 按原逻辑翻页；鼠标滚轮上下翻页，累积小幅滚动并限频，防止触控板惯性连续跳过多页。首页、末页不循环。

放映中双击画面进入**一行固定四页、可纵向滚动的预览**，再双击指定缩略页回到该页放映。预览状态下滚轮只滚动预览，不触发单页翻页。Esc 从放映或预览退出，包括浏览器接管 Esc 退出原生全屏的情况；恢复进入前的视图、每行页数及编辑开关，并保留当前所选页。编辑时原有双击选字行为不受普通视图影响。放映状态不写入保存文件，保存时仍保留进入前的常规滚动视图设置；打印样式移除放映布局约束。验证原生全屏、拒绝全屏的降级、双击导航、滚轮限频、边界、Esc、保存重开与来源深链接。

**放映中的局部缩放与拖动：** 单页放映时按住 Ctrl 滚动滚轮，以鼠标所在位置为锚点缩放幻灯片，范围 **100%–400%**。拦截该组合的浏览器默认页面缩放，不能改变整个工具栏、浏览器页面比例或触发翻页。原始100%表示完整画布适应屏幕；放大后按住鼠标左键拖动查看细节，使用 pointer capture，拖动范围按放大后的画布与可视区域计算，避免把画布拖离屏幕。拖动不触发文字选择、图片拖出、来源链接跳转或双击预览；pointerup、pointercancel、丢失捕获及窗口失焦都需释放拖动状态。

**Esc 按层级处理：** 若当前放大，第一次短按 Esc 只恢复100%并清除拖动偏移，保留放映；在100%时再按一次退出放映及原生全屏。忽略键盘自动重复，不能一次长按意外执行两层网页操作。原生全屏后尝试 `navigator.keyboard.lock(['Escape'])`，让网页在浏览器允许时处理该按键；退出时释放锁，不锁其他按键。浏览器可能要求键盘锁权限；若不支持或拒绝，原生 Esc 可能先退出浏览器全屏，此时恢复100%并保留窗口放映，下一次 Esc 再退出。不得保证所有浏览器均能阻止其原生全屏退出行为；浏览器保留长按 Esc 强制退出通道。依据见[Chrome Keyboard Lock 说明](https://developer.chrome.com/articles/keyboard-lock)。

切换到其他页、进入四列预览或退出放映时重置缩放与平移；预览滚轮仍用于滚动，不允许 Ctrl＋滚轮改变整个浏览器比例。缩放、平移及拖动状态仅用于当前放映，保存 HTML 时清除临时类和变量，打印时禁用 frame 的放映变换。验证真实 Ctrl＋滚轮、放大后左键拖动、上下限、两次 Esc、窗口降级、翻页与预览重置，以及保存重开后回到正常视图。

“编辑文字”开启后显示两个选区格式控件：**加粗／取消加粗按钮**，以及**颜色单选下拉框**（恢复原色、科技蓝 `#005B94`、钢铁红 `#A31418`）。先在同一个可编辑文本块内选中文字，再点击加粗按钮或选择颜色；下拉框操作也必须保留并恢复原选区，加粗按选区现有状态切换，混合字重选区先统一加粗，颜色只改所选字符。“恢复原色”按各处原本颜色恢复，可能为深色、白色、蓝色或红色，不能统一设为黑色，也不能清除加粗、字号、链接等其他格式。首次编辑前按元素记录 `--original-text-color`，并用 `data-original-colors` 标记已记录的文本块；恢复使用 `color:var(--original-text-color)`，允许同一选区内保留多种原色。颜色基准必须随保存的 HTML 保留，再次打开或退出后重进编辑时不能重录成修改后的颜色。AI 若重新设计既有文本块的原始配色，应同步重置该块及后代的原色基准，避免沿用旧基准。禁止把跨文本块、未选中文字或画布外的选区用于格式化；按钮点击不能丢失选区。保留原生 Ctrl+B 及 Ctrl+Z 撤销能力、字号层级、链接和数学 SVG；数学图片不能通过文字工具改变公式。格式采用可保存的行内样式，保存 HTML 后重新打开必须保留。退出编辑或重新打开文件时隐藏工具、清除临时选区。颜色要结合背景核对可读性，尤其不要把深底白字标题改成低对比度深色字；修改字重后检查换行和边界。验证局部格式不影响相邻文字、重复点击能撤销加粗、颜色准确，并实际保存重开检查。

“保存HTML”克隆文档并内嵌全部图片（包括公式与符号 SVG），保留 `data-tex` 供后续编辑，剔除临时编辑状态，不改变当前页面。保存的副本保留所选滚动视图和每行页数；若从单页展示保存，重新打开进入此前的滚动视图。设置以 `body[data-scroll-view]`、`body[data-grid-columns]` 保存，不依赖浏览器本地存储。本模板已包含本地图片缓存，支持直接双击后保存为独立文件。

新增、替换或改名图片后，运行 `python beike-ppt-template/scripts/embed-assets.py` 刷新缓存；若编辑的是另存的汇报，用 `python beike-ppt-template/scripts/embed-assets.py "汇报副本路径.html"`。脚本只有 Python 标准库依赖，读取副本所在目录的相对图片路径，将缓存写入 `assets/<HTML文件名>.embedded.js` 并更新 HTML 中的引用。**AI 编辑正文时无须读取这个生成的缓存文件或 SVG 轮廓路径**。不要手改缓存，也不要让旧缓存覆盖已替换的图片。公式源码变更时先重绘 SVG，再刷新缓存，不能倒序。图片需为已有本地资产，保存后的独立 HTML 不依赖外部数学 CDN。

打印使用 **960×540pt** 页面，原始 1600×900 画布在打印中缩放为 1280×720 CSS px（比例 0.8），从而保持与上述 PPT 字号换算相同的物理尺寸。每页一张，不打印工具栏、侧栏和备注。确认打印背景图形开启，避免渐变与表格底色丢失。无需用户要求时不额外生成 PPTX 或发布网站。

**PDF 的纸张本身必须是 16:9，而不只是把 16:9 内容缩放进 A4。** A4 横向与 16:9 比例不同，关闭页眉页脚或选择“适合纸张”仍会留下画布外白边。精确 PDF 应将整个 1600×900 画布等比缩放到 960×540pt 页面，页面外不再增加另一层纸张边距；模板内部的安全边距属于版式，正常保留。验收必须核对每一页的 MediaBox 实际宽高，而非只看截图内容像宽屏。

默认使用配套 `scripts/export-pdf.py` 直接生成 PDF，避免系统打印机、A4 默认纸张及浏览器记忆设置。Windows 下双击同目录的 `导出PDF.cmd`，导出 `template.html`；将其他已保存的 HTML 拖到此工具上则导出对应汇报，PDF 默认与 HTML 同目录、同名。命令行用 `python beike-ppt-template/scripts/export-pdf.py "汇报.html" --output "汇报.pdf"`。需要 Python 3.10+ 与本地 Chrome 或 Edge，无需额外 Python 包。脚本使用独立临时浏览器配置，关闭浏览器页眉页脚，导出后校验全部页面为 960×540pt 且页数与 HTML 一致；尺寸或页数不符时拒绝覆盖已有 PDF。字体与公式保持浏览器原生 PDF 渲染，不将整页栅格化。修改网页中的文字后先“保存HTML”，再导出该文件，脚本读取的是磁盘内容。

**浏览器自动添加的日期、网页标题、file:// 路径及额外页码不属于幻灯片，PDF 不应包含这些内容。** “PDF / 打印”按钮及页面内 Ctrl+P 会先显示直接导出工具的用法；“浏览器打印”保留为纸张打印入口。不能把这个入口宣称为跨浏览器保证 16:9 的一键导出，也不能假设关闭页眉页脚就能消除 A4 比例白边。常规打印时关闭“页眉和页脚”、开启背景图形，并按实际纸张核对边距。模板自己的来源说明和页码正常保留。

打印指引位于画布外，通过 `.print-guide` 显示，打印时隐藏，保存 HTML 时移除其 `open` 状态；Esc 只关闭指引，不应同时退出单页展示。打印时清除文字编辑轮廓。若使用 Playwright 等工具导出，明确设置 `preferCSSPageSize:true`、`displayHeaderFooter:false`、`printBackground:true`、零页边距，并进行同样的页面尺寸与页数检查。随附 PDF 是导出时的静态快照，HTML 修改后须重新导出。

多页滚动只影响屏幕预览，打印必须恢复为单列、每张纸一页，并移除当前页的选中边框。打印样式要覆盖网格布局和脚本设置的正文上边距，不能把多页缩略图一起印在同一张纸上。

完成内容后在浏览器执行以下检查，修复发现的问题，再交付：

1. 等待字体、图片及公式就绪，逐页查看总览和单页模式，核对标题、正文与证据是否对应。先核对“00 整体规范 → 目录 → 各章过渡及连续正文 → 附录”的结构，再核对目录、左上标签和侧栏；参考资料不能混入未来计划。
2. 点击“检查排版”，或调用 `checkLayout()` 获取问题数组。它检查章节顺序与目录对应、正文安全区、文本溢出、标题行数、校徽居中、页脚边界、表格内边距和文字边界、履历表五列间隔与居中、并列内容实际下沿与作者页底部末行、公式互斥显示、题目条贴合、变量斜体、父子标题层级、相邻块遮盖与段末孤字。返回空数组仍需要目视复核。
3. 对修改过的母版涉及的全部页面进行截图检查。重点看封面署名列起点、深浅底字色、公式解释完整性、表格相邻数字是否至少隔一字、场景分隔线、图注及页脚。P09 / P16 要有实质内容和均衡密度，不能靠高大空卡片或宽松单元格填满。检查计划表真实底边与下方说明至少相隔 12px，任何遮盖都须修复。实验表仅取 12 / 11 / 10pt；过密时拆页。
4. 至少在桌面宽屏和较窄窗口检查缩放；多页模式核对每行 1–6 页、同排页面选中状态、双击与 Esc 返回、备注展开和跨页文献跳转。标题和校徽尺寸必须由整张画布统一缩放。窄屏下工具栏不能遮住幻灯片。
5. 检查打印预览页数与实际页数相同，每张均为 16:9，末页无空白页，页边没有浏览器添加的日期、标题、路径与额外页码。指引和编辑轮廓不能进入打印内容。若导出 PDF，检查实际页面尺寸和渲染结果。
6. 实际触发一次保存，重新打开下载文件，确认图片、公式、导航与编辑功能可用。修改文字后再检查溢出，不能只验证原始示例。
